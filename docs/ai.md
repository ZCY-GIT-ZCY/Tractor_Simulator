# Enoch 桌规版

PVE 默认运行一名真人与三名 Enoch 桌规版 AI，入口与原来相同：双击 `run.bat`，选择「人机对局」。AI 本地计算，使用 conda base 的 Python 标准库，不下载权重、不安装运行库。

参考项目：[tgoh-ots/shengji-tractor](https://github.com/tgoh-ots/shengji-tractor)，固定提交 [21aa754d5128da8f62a7218c00d97715757240d0](https://github.com/tgoh-ots/shengji-tractor/tree/21aa754d5128da8f62a7218c00d97715757240d0)。在本次查看的候选中，它的手写策略、公开信息跟踪、确定化搜索和相应测试较完整，因此选择其 Enoch 策略作为适配基础。上游未提供能确认普通人类水平的统一测评。

这是 Python 改写版本，不是原 Rust 二进制，策略和预算有所调整，不能将上游的实验胜率直接套用到此版本。AI 标识为 `enoch-table-v1`。MIT 许可与原版权见 [许可全文](../licenses/enoch-MIT.txt)。

## 移植内容

来源文件均位于参考提交的 `core/src/bot/`：

| 来源 | 本地对应 | 保留或修改内容 |
| --- | --- | --- |
| heuristics.rs: bid_strength_enoch / trump_pair_structure | bid_strength / EnochPolicy._bid | 主牌长度、大小王和副牌 A/K 控制，对子额外加值，拖拉机额外加值；相邻关系改为本裁判定义 |
| heuristics.rs: choose_kitty_enoch / enoch_point_budget | choose_bury | 保留主牌、级牌、A 和对子保护，优先断短门；按本桌规的指数扣底倍率收紧埋分预算 |
| heuristics.rs: score_lead / enoch_lead_bonus | rank_moves | 兑现副牌大牌、优先强对和拖拉机、长门与对家缺门配合，避免早期单独领出大王和级牌 |
| heuristics.rs: score_follow | rank_moves | 对家已稳拿时喂分，仍可能被杀时保守喂分，敌家赢时少送分、保留主牌和对子；胜负比较使用本裁判 |
| search.rs / policy.rs: determinized search | EnochPolicy._search | 同一批未知牌世界比较候选，手写策略 rollout，完整批次才纳入均值；按配对收益与不确定性保守改选，限时退回手写策略 |
| determinize.rs: public constraints | Knowledge / sample_world | 已出牌、公开亮牌、甩错暴露牌、跟牌暴露的缺门，自己知道的最新底牌，实体牌和手牌张数守恒 |

保留原策略的主要启发式数值，但出牌候选生成、搜索状态构造和终局价值按本环境重写。未移植找朋友、炸弹、可选规则、ONNX prior、全知模式、上游所有实验特征开关或所有历史对子约束。确定化采样是近似信念，不是对未知牌的精确后验。

## 本桌规适配

规则唯一来源为 `双升游戏规则.md`；AI 不导入参考项目的规则引擎。合法跟牌由 `rules.validate_play` 检查。每个搜索世界都是独立构造的 TractorEnv，使用与真人牌桌相同的 `step`、甩牌检查、轮次比较和结算：

- 亮主、反主、加固和反底仅使用当前裁判给出的 `bid_options`。最后确认、反底顺序、不能反自己、对大王终止、最近一次扣底归属和庄家首出均由本裁判处理。
- 打 2 的首局抢庄在摸牌和拿原始底牌前的亮主阶段，只要有合法亮主、加固或反主动作就执行，不设手牌强度门槛。优先最强亮牌级别，再按本手牌的主牌潜力选花色；花色对、小王对、大王对都可反，不能用王对首次亮主或反自己。拿底后不再改变坐庄者，反底恢复常规策略判断。
- 跟门不足必须出完该门；最长拖拉机优先，然后剩余拖拉机和对子。无主及去掉级牌后的相邻关系按本环境判断。
- 杀甩牌须完整匹配组成牌型，比大小仅比较最大牌型。相同时先出者赢。策略和搜索调用同一比较函数。
- 甩错尝试总张数 n 罚 10n 分，实际强制出最小牌面单或对，罚分按双方归属计入闲家分数。策略仅生成公开信息可证明不被同门压过的甩牌；预校验仍不预测真人甩牌成败。
- 扣底倍率按末轮实际领出的牌型内对子数 p 计算 `2**(p+1)`；领出六张副牌单张，被主牌三连拖杀仍只 ×2。含 J/A 的最终获胜手触发相应特殊降级；必打等级和永久已打记录由原结算逻辑决定。搜索终局收益也考虑实际升级、降级及 A 级胜负。
- 底牌保密。当前底牌主人可在搜索中使用自己刚扣的八张；曾经拿过底但之后别人重扣的人不能把旧底当成当前底牌。

## 信息与服务接口

`EnochPolicy.act(observation)` 只接收行动座位自己的 `env.observe(player)`。传入 `hands` 或 `deck` 会明确拒绝。策略没有 live env、export_state、服务器或前端引用。其他座位的模拟手牌来自采样，绝不读取真人对局的隐藏状态。

观察新增 `played_cards`（本局所有公开已出实体牌）和 `public_history`（本局亮牌、拿底/扣底者、实际出牌和甩错的公开记录）。扣底记录只有玩家编号，不含扣下的牌。完整公开记录解决原 `events` 仅保留最后 80 条而导致 AI 忘记早期出牌的问题。旧 checkpoint 加载时重建此记录。

网页快照新增 `ai: {id, name}` 和 `bot_thinking`；不发布采样世界或候选评分。房间四座各自拥有策略实例。最多四个后台工作线程，每房间最多一个正在计算的决策。计算时释放房间锁，完成后检查环境 revision、当前行动者及是否仍允许自动行动，丢弃过期结果。PVP 可用 AI 补位，真人也可主动开启、取消自己座位的 AI 托管；托管直接复用该席的 EnochPolicy，不修改其亮牌策略。原策略并非只在摸完后才亮主，摸牌途中也可能根据当前手牌亮主。

「随机一步」仍是用户主动调用的随机辅助；PVE 的「托管本局」会临时让本人的席位也使用 Enoch，暂停后恢复本人操作。自对弈保持随机托管。

跟牌时给对家垫分也计算所消耗牌的保留价值。修复前，无法赢当前轮的跟牌只要包含分牌，就遗漏了这一代价，可能将带 5 分垫普通主与带 5 分垫级牌评成同分。现已修正手写排序及模拟后续使用的同一评分；对家领对子加单张、自己全主但没有对子时，构造回归中的手写版与搜索版都保留级牌 2。合法跟型、对子保护与送分风险仍参与判断，不保证任何局面都不垫级牌。

## 控制与分数的取舍（2026-10-12）

后续核对 9999 房间的六份打 2 记录。04:30 结束那局，第 142 个动作中，AI 给对家的黑桃 K 对加黑桃 10 对垫红桃 7、方片 10 对和红桃 2；它还有普通主可垫，红桃 2 并没有使这一手赢牌。用部署前版本复算，三个搜索种子都重现了这一选择。新版复算四个种子均保留这张红桃 2。原记录保留在本地 runtime，不加入 Git 或部署包。

04:53 结束那局，第 132 个动作则是另一类情况：AI 最后跟牌，用方片 2 压过敌家的草花 A，取得出牌权，后面仍出了草花 A、Q。这不是无法杀牌时的垫牌；夺出牌权是否值得仍由后续收益评估，不据此宣称该选择最优。

本次在此前漏算代价的修复之外，补充以下判断：

- 搜索中未打完局面的估值区分普通主、正／副级牌、大小王，并计算对子和拖拉机的剩余控制。拖拉机相邻关系使用本裁判，包含跳过当前级牌与无主规则。
- 分数收益在 40 分等升级边界附近加权，80 分上台边界权重更高。未完成模拟的控制权重参考剩余牌面分数和该采样世界的底分；J／A 级保留末轮控制价值。真实终局仍按裁判的实际扣底倍率和特殊降级结算，不能仅用剩余桌面分数断言闲家已不可能上台。
- 给对家送分和接过出牌权都考虑消耗的控制；确实增加获胜保障时可以少扣代价。副牌大牌尚未被同门压过，并不等于对家已稳拿：尚未行动的敌家仍可能断门杀牌。稳拿证明只使用本人手牌与公开信息，按实际领出的最大牌型比较。
- 跟牌搜索至少保留一种可以赢的候选和一种不能赢的候选（两类均存在且预算允许时），避免大量相近的垫牌挤掉唯一的完整杀牌结构。
- 同一个未知牌世界内先比较候选与手写首选的收益差，再统计均值和标准误。样本少或差异波动大时，提高改选门槛；一致且足够大的收益仍能改选。诊断只记录汇总数值，不发布采样手牌或候选私牌。

这些是启发式修正，不是“禁止垫级牌”。不能杀敌家、但垫 10 分会送到 80 分时，可以舍弃无分的 2 保护 10；对家稳拿时仍可送分；级牌能赢敌家主 A 时仍可夺回出牌权。新增用例同时检查这些允许舍大牌的情况和应保留级牌的情况。

验证包含后端全量 180 项、前端 81 项，以及独立规则审计的 8 局新旧版本对战。新版赢 3/8，不能据此证明整体强度提高或普通人类水平。该小样本使用 600ms／2 世界预算，并非网页默认 12 世界；更多真人对局仍是必要的强度检验。数据见 [控制估值验证](ai-control-validation.json)。

## 预算与本地接口

默认每步最多约 600 毫秒、12 个世界、6 个根候选。前段 rollout 为两轮，剩余最多八张牌时尝试推演到本局结束。唯一候选不搜索。预算包含候选生成；少数复杂牌型的单次裁判计算无法在函数内部中断，可能略超时。未完成一整批候选时丢弃该批，无法完成任何批次时使用手写首选。

PowerShell 可调整本进程的预算，之后重启服务：

```powershell
$env:TRACTOR_AI_TIME_MS = '1200'
& 'C:\Miniconda\python.exe' -m tractor_sim --serve --headless --port 8765
```

设为 0 仅使用手写策略。程序中可使用：

```python
from tractor_sim import EnochPolicy
policy = EnochPolicy(seed=42, time_ms=600, worlds=12)
action = policy.act(env.observe(env.current_player))
```

CPU 搜索不需要 GPU；Python 工作线程主要保证网络请求响应，受 GIL 影响，同时多桌思考会降低吞吐，当前版本未使用多进程搜索。

## 验证范围

新增测试覆盖全部 13 个等级共 39 局完整对局、候选合法性、未知牌采样守恒与缺门约束、最新/旧底牌区分、公开记录与旧快照恢复、最大牌型比较、对家喂分、搜索不修改真局、输入隔离，以及后台慢策略不锁桌和过期决策丢弃。

使用 `python -m tools.benchmark_ai --seeds 16 --time-ms 250 --worlds 2` 可复现双 Enoch 对双 Random 的对局。同一牌序分别让 Enoch 做庄家与闲家，等级轮换 2 至 A，逐局数据保存至 [ai-benchmark.json](ai-benchmark.json)。该基准仅检查弱基线上的表现，不能证明普通人类水平；接下来应以真人盲测对局评估。

2026-10-11 本机实测：32 局胜 29 局（90.625%），1,230 次 AI 出牌决策，1,830 批搜索完成；平均 143.6 毫秒，95 分位 251.6 毫秒。本次基准使用较小的 250 毫秒 / 2 世界预算，网页默认仍为 600 毫秒 / 12 世界。牌序相同但策略的亮主/反底会改变后续牌局，不宣称这是独立同分布的人类等级测评。

后续按网页默认预算做了两局前端手动对战、32 局强度测量和独立规则核对。对 Random 赢 16/16，对同源无搜索手写版赢 9/16；不能据此证明稳定的搜索优势或平均人类水平。详情见 [实际试玩评估](ai-evaluation.md)。
