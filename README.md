# 双升 · Tractor Simulator

需要在对局中更新前端、后端或 AI 时，可首次启用常驻网关，之后通过 `python tools/update_live.py` 保留房间和牌局滚动替换应用。首次从旧服务切换须等牌局结束；详见 [不停服更新说明](docs/live-updates.md)。

本地和服务器均可运行的双升仿真器。唯一桌规是 [双升游戏规则.md](rules/双升游戏规则.md)，原录音整理稿备份在 `docs/双升游戏规则.录音原版.md`。没有使用 Botzone 的裁判，也没有复用其他仓库的环境代码。牌面、桌面和动画直接用 HTML/CSS/SVG 绘制，无外部字体、图片或 CDN。

## 启动

需要 Python 3.10 或更新版本，无第三方运行依赖。后端、前端、准确规则、AI 和回放功能均随仓库提供，无须下载模型，也无须 pip 安装。请在项目根目录启动。

```bash
git clone https://github.com/ZCY-GIT-ZCY/Tractor_Simulator.git
cd Tractor_Simulator
python -m tractor_sim
```

默认在 `http://127.0.0.1:8765` 启动并打开浏览器。Ctrl+C 停止服务。Linux/macOS 如使用 `python3`，将命令中的 `python` 替换为 `python3`。Windows 也可双击 `run.bat`；要给异地朋友提供网页入口，双击 `启动双升联网游戏.bat`。

不使用 Git 时，可从 [Releases](https://github.com/ZCY-GIT-ZCY/Tractor_Simulator/releases) 下载 `TractorWeb.zip`，完整解压后进入 `TractorWeb` 目录运行相同命令。Windows 启动脚本优先使用已有 conda base，否则使用 PATH 上的 Python。开发目录旁有原始 `双升游戏规则.md` 时优先读取它，否则读取仓库 `rules/` 内的准确副本。

从新电脑部署、服务器常驻运行、反向代理和更新方法见 [部署说明](docs/deployment.md)；免域名邀请链接见 [公网使用说明](docs/internet.md)。

重复运行或双击启动脚本时，会先识别占用该端口的服务：若是同一监听地址的双升服务，则打开已有牌桌并保留现有牌局；若是其他程序，则提示换端口，不停止任何进程。另起一桌服务可传 `--port 8766`。

纯仿真、完整升级比赛及可验证重放：

```powershell
& 'C:\Miniconda\python.exe' -m tractor_sim --headless --episodes 100 --seed 42
& 'C:\Miniconda\python.exe' -m tractor_sim --headless --episodes 3 --full-match --seed 42 --output docs/run.json
& 'C:\Miniconda\python.exe' -m tractor_sim --replay docs/run.json
```

`--level 11` 表示初始 J；`--no-auction --banker 2` 表示不抢庄、2 座坐庄。网页对局的配置在入座面板选择，CLI 的这三个参数只配置 headless rollout。

摸牌、出牌和询问均逆时针（南→东→北→西）。摸完 25 张后进入拿底前确认。打 2 抢庄时，成功加固／反主后继续询问其余三家，仍可被王对反主抢庄；三家不反或亮到大王对才拿底。非抢庄局拿底前成功反主只改变主牌，原始八张底牌仍由庄家拿；成功反主／加固后结束确认，由庄家拿底扣底。其他抢庄流程保持原设定。扣底后的反底始终拿最近一次实际扣下的八张牌，不改变庄权。

摸牌期间可提前选牌，任意座位可随时用同一按钮亮主／反主，按服务器收到请求的先后裁判；后来同强度或较弱亮法提示无效。亮主不多发一张牌，只有当前摸牌者继续摸牌才发下一张。后续亮主确认与反底仍按轮询进行。当前主由本人确定时禁止反自己，仅单张级牌可同门加固为对子。末轮扣底倍率按实际领出的牌型计算，甩两单被对王杀仍只 ×2。

自己的手牌始终排在固定区域内，牌多时自动分成两行重叠，不把两端挤出屏幕。手牌标题和跟牌提示显示本局实际等级；跟牌校验绑定牌桌版本，同时核对服务端级牌与主花色，局面不同步时先刷新再允许提交。

## 牌桌操作

摸完牌后，实时亮主继续开放 6 秒，牌桌显示剩余时间；亮主不会延长窗口。时间到后由服务器自动进入拿底前确认，仍无人亮则沿用抢庄重洗／普通局翻底定主流程，无需最后摸牌者继续点击。AI 的不亮或迟到决策不会提前结束或越过这个窗口。

- **自对弈**：四家明牌，底部显示当前行动者的可操作手牌，侧面与上方显示另外三家。可替所有人亮主、扣底、出牌；侧面长手牌可滚动。“随机一步”执行当前行动，“托管本局”让四家随机走完，随时可暂停。跟牌只有一种合法牌面组合时自动预选，玩家点击“出牌”确认；有多种选择则手动选牌。悬停手牌只上移，保留原来的叠放顺序。副牌花色尽量黑红交替，主花色在右侧、常主更靠右；出完某门后自动按剩余花色重排。摸牌时右侧显示本次摸到的单张，窄屏移到手牌旁；PVE/PVP 只显示本人的摸牌，其他人摸牌时清空。
- **PVE**：选择自己座位，只看本人手牌；其他三家默认由 **Enoch 桌规版** 操作，轮到自己自动停下。AI 结合手写策略与未知牌采样搜索，按本项目桌规决策，无需模型、GPU 或额外安装。适配和强度验证见 [AI 说明](docs/ai.md)。
- **PVP**：通过邀请链接或相同房间号在**同一服务器**进入同桌。点击东南西北任一空席预选，按“确定选座”才占用并公开昵称，按“取消选座”释放；确认冲突由服务器原子检查。南 0 / 北 2 为青队，西 1 / 东 3 为金队。首位进入者配置本场并成为房主，四席就绪后由房主点击“开始对局”。缺人时房主可逐席或一键添加本地 Enoch AI；开局前可移除 AI。开局后座位固定，真人主动离开的空席仍可由新人或 AI 接手。房主负责开始下一局。

选牌点击一次选中，再点击取消；Enter 提交，Esc 清空。PVE/PVP 出牌时可在别人行动期间预选自己的手牌，轮转不会清空；轮到本人后按当前领出的牌校验，通过才可提交。唯一合法跟牌仍自动预选。发牌中“自动摸牌”在轮到本人后等待 1 秒继续发牌，同一次摸牌的亮主／AI 思考等状态更新不会重新计时，摸到级牌或凑齐王对不再自动暂停；实时亮主阶段预选和提交亮牌也不会关闭自动摸牌。多人模式按逆时针轮转，每名开启自动摸牌的真人在自己的摸牌回合等待 1 秒；本人两次收到牌之间还包含其他三家的行动、网络和调度时间。可手动点“暂停摸牌”，摸完后进入六秒亮主窗口时自动结束摸牌。扣底须选八张。

PVP 牌桌右下方可随时点 **AI 接管**，由现有 Enoch 桌规版托管自己的座位，四家都能看到昵称旁的 **AI 托管** 标志。托管保留真人的座位、昵称和私牌，可处理摸牌、亮主、扣底、反底及出牌；点击 **取消 AI 托管**立即恢复手动，尚未执行的旧 AI 决策作废。开关只控制本人，跨局保留直到取消或离开房间；托管中的玩家断线不暂停全桌，其余手动玩家仍按原断线规则暂停。真人庄家的终局底牌核对仍须本人确认，房主仍负责开始下一局。AI 的原有亮牌策略不变，原策略在摸牌途中也可能亮主。

所有出牌都由服务端预校验。非法跟门、跟型、张数、混门领出、非法亮主直接禁用提交。**甩牌没有成败预测**：同门甩牌允许提交，甩错时才罚本次尝试总张数 ×10，并强制实际出最小单张或对子。预校验和合法动作枚举不查看其他隐藏手牌来过滤甩牌。

对局进行中底牌不明示；仅无人亮主、翻底定主时提前公开。拿底时八张牌收入手中，玩家知道自己拿过和扣过的牌。亮主、加固或反主的牌保持在亮牌者座位前，其他三家收到昵称与主门的短暂提示。末轮结束先公开最终八张底牌，在牌桌下方列出抓分、底牌分数 × 倍率、甩牌罚分和闲家总分。本局庄家确认后，四家同时弹出升级、J/A 降级及下一位庄家的结果；AI 庄家展示六秒后自动确认，自对弈可代庄家确认。必打记录只在该队作为庄家方获胜（闲家最终总分低于 80）时登记，按队永久保留；守庄失败不算完成，闲家高分上台也不能离开尚未坐庄获胜的必打级。关闭结算后可点击牌桌左上“本局结算”再次打开。

## 历史对局与回放

每局结算自动保存到 `runtime/history/`，以打几与时间命名。点击 **历史对局** 直接查看按日期排列的记录，支持逐步回放、自动播放、0.2×～5× 连续变速、时间线跳转和四家手牌查看；服务重启后记录仍在。详见 [回放说明](docs/replay.md)。

## 网页多人联机

双击 **`启动双升联网游戏.bat`** 启动本地服务与 HTTPS 公网隧道，验证连通后自动打开游戏首页，窗口显示可分享的公网入口。进入“好友房间”，房间号留空创建新房间，再点击“邀请牌友”分享带房间号的组队链接；朋友无需下载，在手机或 PC 浏览器打开即可。确认选座或补齐 AI 后由房主开始。结束时双击 **`停止双升联网服务.bat`**，或在启动窗口按 Ctrl+C。原 `run-public.bat`、`stop-public.bat` 仍可使用。

临时入口每次重建会变化；固定域名模式也已接入 `internet.json`。详细启动、重连、域名配置和故障处理见 [公网使用说明](docs/internet.md)。发布包位于 `dist/TractorWeb.zip`，包含前后端和准确规则副本；用 `python tools/package_web.py` 重建。

好友房间主动离开后 AI 自动接替；新玩家在开局前或两局之间选择 AI 席位并确认接手。对局中或四席均为真人时拒绝新加入，托管真人的席位仍归原玩家。最后一名真人离开后 AI 打完本局即停。

Linux 可用 `python3 tools/install_services.py` 安装开机常驻的游戏服务和独立隧道，无需公网 IP。部署与管理见 [Linux 常驻说明](docs/linux-service.md)。隧道重连不重启游戏，验证成功后入口保存在 `runtime/public-url.txt`。

Cloudflare 出口不可用时，Linux 可改用 SSH 中继：`python3 tools/install_services.py --provider localhost-run --tunnel-only`。这会保留已有游戏进程，只切换公网入口；免费域名会变化且有限速，详见上述常驻说明。

## 服务器运行

在 Linux 或 Windows 的源目录运行：

```bash
python -m tractor_sim --serve --headless --host 0.0.0.0 --port 8765
```

局域网玩家访问 `http://服务器局域网IP:8765`。公网使用反向代理提供 HTTPS，再将流量转发到本机监听端口；同桌玩家共享同一个服务器进程。标准库多线程 HTTP + 最长 5 秒的长轮询，不需要 WebSocket、数据库或 GPU。不要把四位玩家分配到互不共享状态的多个服务进程。

房间号是入场口令，不是用户账号。客户端用随机 Bearer token 保留座位，页面刷新可恢复，重新打开同一浏览器也可点击回到上次牌桌；PVP 未开启 AI 托管的玩家断线 25 秒后暂停，重连继续。主动离开释放座位，新人可接手该座位。房间和会话保存在内存，**服务器重启后清空**；已完成局的历史回放持久保存。本版未实现账号、个人战绩或跨进程房间。已有临时 HTTPS 公网联机实测；固定域名配置需自行提供 domain 与 tunnel token。

## Python 接口

```python
from tractor_sim import TractorEnv, GameConfig, RandomPolicy

env = TractorEnv(GameConfig(initial_level=6, auction=False, banker=0), seed=42)
policy = RandomPolicy(seed=43)
while env.phase not in ("round_end", "match_end"):
    actor = env.current_player
    observation = env.observe(actor)
    action = policy.act(observation)
    assert env.validate_action(action, actor)["valid"]
    transition = env.step(action, actor)
print(env.result)
```

这是四人轮流行动接口，不会暗中执行对手。每次 `step` 后的 observation 属于**下一位当前行动者**；训练时应先存当前行动者的 observation/action，再按玩家整理轨迹，不能直接把连续两步视为同一玩家的 MDP 转移。

`StepResult.rewards` 为四个固定座位的原始即时得分奖励：本步闲家得分变化 ΔS，闲家两座各 +ΔS，庄家两座各 −ΔS；包括甩错和末轮底分。开始下一局为零奖励。它不是胜率或升级奖励；未来训练可在外层定义自己的终局回报。`terminated` 仅整场 A 级坐庄获胜时为真；一局结束看 `info["round_ended"]`，使用 `next_round` 接着打，或 reset 开新样本。`truncated` 固定为假。

更多动作、牌编号、观察字段、快照与 HTTP 规范见 [接口文档](docs/api.md)。`iter_legal_actions` 是按相同牌面组合去重的惰性穷举，扣底和大手甩牌的组合数很大；没有截断或假装全部枚举完。RandomPolicy 用合法跟牌构造器，不枚举整张动作表；领出随机选择单、对、拖拉机，**不是全部合法动作的均匀采样**。

替换网页 AI 只需实现 `act(observation) -> action`，再注入策略工厂：

```python
from tractor_sim.server import TractorServer
from my_policy import MyPolicy

server = TractorServer(("127.0.0.1", 8765), policy_factory=lambda seed: MyPolicy(seed))
try:
    server.serve_forever()
finally:
    server.server_close()
```

每个房间为四个座位分别创建策略实例。策略只收到该座位可知信息，后台思考不持有牌桌锁，过期决策不会落到新状态上。异常策略会暂停牌桌并记录服务端日志。PVE 默认使用 EnochPolicy，自对弈的随机一步与随机托管保留原行为；显式注入 policy_factory 可覆盖默认策略。

## 验证

```powershell
& 'C:\Miniconda\python.exe' -m unittest discover -s tests -v
node --test tests/*.cjs
```

测试覆盖主副牌排序和连续性、优先跟拖与对子、完整杀牌、只比较最大牌型、甩牌原子校验与罚分、反底庄权、扣底倍率、得分边界、必打记录、J/A 降级、可见信息、快照重放，以及 HTTP 四人房间、鉴权、旧版本动作、断线恢复和路径隔离。另执行了随机完整升级比赛与浏览器实玩；验证记录在 [validation.md](docs/validation.md)。

当前是 CPU 参考裁判，便于逐条验证规则；没有实现 GPU 仿真，也没有固定任何模型、牌型 mask 或训练框架。以后优化应与这套裁判做差分验证。
